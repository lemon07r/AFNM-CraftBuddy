# Phase 1: Project Setup

## Goal

Prepare the repo for Rust/WASM development in a way that is compatible with the actual runtime constraints and friendly to AI-agent implementation.

## Build pipeline decisions

Use this build shape:

- `wasm-pack --target web`
- raw wasm-pack output kept as a generated artifact
- post-build inline step that generates a TypeScript module with embedded bytes/base64

Do not enable webpack `asyncWebAssembly`.

## Recommended scripts

Add scripts along these lines:

```json
{
  "wasm:build:core": "wasm-pack build crates/craftbuddy-engine --target web --release --out-dir ../../src/wasm-pkg",
  "wasm:build:dev:core": "wasm-pack build crates/craftbuddy-engine --target web --dev --out-dir ../../src/wasm-pkg",
  "wasm:inline": "node scripts/wasm/inline-wasm.js",
  "wasm:build": "bun run wasm:build:core && bun run wasm:inline",
  "wasm:build:dev": "bun run wasm:build:dev:core && bun run wasm:inline",
  "wasm:test": "cd crates/craftbuddy-engine && cargo test",
  "wasm:bench": "cd crates/craftbuddy-engine && cargo bench",
  "typecheck": "tsc --noEmit",
  "release:validate": "bun run typecheck && bun run test && bun run build && bun run docs:check"
}
```

Update `prebuild` so the inline WASM asset exists before webpack runs.

## Recommended files/directories

```text
crates/craftbuddy-engine/
scripts/wasm/
src/wasm-pkg/                       # generated by wasm-pack, gitignored
src/optimizer/wasm/generated/       # generated inline byte module, gitignored
```

## Repo hygiene improvements worth landing early

### 1. `.gitattributes`

Add it if missing so `.wasm` is treated as binary and line endings stay normalized.

### 2. Agent entrypoint files

Add lightweight repository pointers for common coding agents if missing:

- `CLAUDE.md`
- `GEMINI.md`
- `.clinerules`
- `.cursorrules`
- `.windsurfrules`
- `.github/copilot-instructions.md`

Each should point back to `AGENTS.md` and `docs/project/START_HERE_FOR_AGENTS.md`.

### 3. Generated artifact ignores

Ignore:

- `src/wasm-pkg/`
- `src/optimizer/wasm/generated/`
- `crates/craftbuddy-engine/target/`

## Suggested immediate milestone

The first setup milestone should not include real optimizer logic. It should only prove:

- Rust crate builds
- inline asset generation works
- webpack bundle still builds
- the mod can call a trivial WASM export successfully

That gives the later phases a working delivery path before semantic work starts.
